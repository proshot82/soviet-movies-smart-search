# План работы над проектом

**Цель:** полная база советских кинофильмов, телефильмов, телеспектаклей и мультфильмов 1917–1991 годов с максимально полными сюжетными аннотациями и умным поиском по ней. Поиск работает локально (`serve.bat`) и на GitHub Pages (`docs/`).

Состояние на 19.10.2026. Цифры получены запросами к `gosfilmofond.db` в этот день.

## 1. Что уже есть

**База `gosfilmofond.db`** (Git LFS, 777 МБ): 11 394 фильма, 54 005 фрагментов, у всех есть эмбеддинги.

| Тип (`films.kind`) | Фильмов | Откуда |
|---|---|---|
| кинофильм | 7144 | 1918–1987 — печатные каталоги ГФФ; 1988–1991 и пропуски — списки владельца |
| телефильм | 1626 | список телефильмов владельца (аннотации в основном с kino-teatr.ru) |
| фильм-спектакль | 1359 | kino-teatr.ru (в `source` у 1565 фильмов есть URL) |
| мультфильм | 654 | каталоги ГФФ, почти все до 1969 года |
| не игровое | 549 | концерты, хроника: каталоги ГФФ и списки |
| фильм-опера/балет | 62 | |

- **`film_id` 1–7174** — каталоги Госфильмофонда 1918–1987. **Эти записи закрыты: аннотации не трогаем.**
- **`film_id` 7175–11394** — добавлены 19.10.2026 из `Кино_СССР сводный каталог.xlsx` и `Кино_СССР телефильмы и пропуски включить в базу.xlsx`. Отчёт сверки — `imports/2026-10_телефильмы_и_пропуски_отчёт.xlsx`.

**Инструменты:**

| Команда | Что делает |
|---|---|
| `python film_search.py serve` / `serve.bat` | локальный поиск: слова + смысл + переоценка моделью gpt-5.5 |
| `python tools/xlsx_to_json.py …` | сверка xlsx с базой → JSON для импорта и отчёт xlsx |
| `python film_search.py import файл.json [--dry-run]` | новые фильмы; запись с `film_id` — правка существующего |
| `python film_search.py embed --resume` | эмбеддинги новых или изменённых фрагментов |
| `python pages/build_site.py` | данные сайта `docs/data/` (31 МБ) из базы |
| `python pages/check_parity.py` | сверка браузерного движка `docs/engine.js` с Python (нужен node ≥ 22) |
| `GFF_cowork/scripts/p4/bench/` | бенчмарк поиска: 85 запросов, только кинофильмы ГФФ |

Порядок пополнения расписан в `tools/README.md`.

## 2. Правила для любой сессии

1. **Аннотации `film_id` 1–7174 не менять.** Метаданные (тип, студию) — только по согласованию с владельцем.
2. **Перед записью в базу:**
   - сделать копию `gosfilmofond.db`;
   - прогнать `import --dry-run`;
   - после импорта: `embed --resume` (**никогда без `--resume`**: без него пересчитываются все 54 тыс. фрагментов) → `stats` → `pages/build_site.py` → `pages/check_parity.py`.
3. **Изменили поиск в `film_search.py` — меняйте и `docs/engine.js`.** Затем `check_parity.py` должен показать полное совпадение.
4. **`film_search.py` хранится с переводами строк CRLF.** Редактировать, не меняя их, иначе дифф затронет весь файл.
5. **База в Git LFS:** каждая загруженная версия занимает ~0,8 ГБ из бесплатных 10 ГиБ (сейчас занято ~1,4 ГБ). Коммитить базу пачками, а не после каждого шага.
6. **Расходы OpenAI:**
   - эмбеддинг ~ $0,13 за 1 млн токенов (цена взята из кода, не проверялась); 4220 фильмов с короткими аннотациями обошлись в $0,15;
   - переоценка gpt-5.5 — около 20 тыс. входных токенов на каждый поиск.
7. **Чужие сайты:** соблюдать `robots.txt` и условия использования, проверки «я не робот» не обходить. Указывать источник аннотации в `films.source`.
8. **LLM не сочиняет аннотации:** велик риск выдуманных подробностей. Модель можно использовать для классификации («описывает ли текст сюжет»), чистки и сверки.

## 3. Этапы

### Этап 1. Все фильмы из списков владельца в базе — ГОТОВО (19.10.2026)

- Добавлено 4220 фильмов. Повторная сверка находит в базе все 11 287 записей обоих xlsx.
- Импорт больше не теряет разные фильмы с одинаковым названием и годом, умеет `--dry-run` и правку по `film_id`.

### Этап 2. Полные сюжетные аннотации для фильмов 7175–11394 — СЛЕДУЮЩИЙ

**Проблема.** Аннотации короткие:
- у 2497 из 4220 фильмов короче 300 символов;
- 604 обрываются на «…» или «...»;
- часть описывает не сюжет, а судьбу фильма.

Пример: «Семнадцать мгновений весны» (film_id 8327) не находится по описанию сюжета даже среди 62 кандидатов. Его аннотация звучит как «вошёл в анналы советского кино, в анекдоты…».

**Что проверено 19.10.2026 о kino-teatr.ru:**
- `robots.txt` разрешает разделы `/kino/` и `/teatr/`, запрещает `/search/`;
- после нескольких автоматических запросов из облачного окружения сайт показывает проверку «Роботам запрещено посещать наш сайт. Подтвердите, что вы не робот». **Автоматический сбор оттуда исключён;**
- страница `/kino/movie/sov/464/annot/` («Белая земля», 1970) содержит ровно тот же текст, что и база, вместе с многоточием.

Где на kino-teatr лежит «полная» аннотация — **неизвестно, спросить владельца** и попросить пример URL.

**Задачи:**
1. **Список работ** — новый `tools/annotation_worklist.py`. Выгрузка xlsx: film_id, название, год, тип, студия, длина аннотации, признаки «обрыв» и «не сюжет», URL источника, пустая колонка «Новая аннотация», колонка «Источник новой аннотации».
   - Признак «не сюжет» — классификация дешёвой моделью по тексту аннотации; затраты прикинуть заранее.
   - Порядок: обрывы → «не сюжет» → самые короткие.
2. **Источники** — выбрать вместе с владельцем, у каждого проверить условия использования:
   - kino-teatr.ru — только вручную, владельцем или в его браузере;
   - Википедия — API, лицензия CC BY-SA, нужно указание авторства; раздел «Сюжет»;
   - «Энциклопедия отечественного кино» (russiancinema.ru), ruskino.ru — проверить `robots.txt` и условия;
   - каталоги Гостелерадиофонда, печатные справочники по телефильмам — если есть сканы.
3. **Применение:**
   - заполненный xlsx превратить в JSON-правки `{"film_id", "annotation", "source"}`: новый режим в `tools/xlsx_to_json.py` или отдельный скрипт;
   - затем `import --dry-run` → `import` → `embed --resume` → сайт.
   - При правке аннотации импорт сам пересобирает фрагменты и удаляет старые эмбеддинги.
4. **Готовность:**
   - обрывов на «…» — 0;
   - доля аннотаций короче 300 символов среди 7175–11394 заметно ниже 59%;
   - «Семнадцать мгновений весны» и 10–20 других известных телефильмов находятся по описанию сюжета (см. этап 5).

### Этап 3. Полнота каталога

1. **Мультфильмы** — главный пробел. В базе 654, но после 1969 года только 4 («Баллада о Беринге…», «Маяковский смеётся», две «Марии, Мирабелы»). Нет «Ёжика в тумане», «Ну, погоди!», «Винни-Пуха».
   - Возможный источник — база animator.ru, условия не проверялись.
   - Объём, вероятно, сотни или тысячи коротких мультфильмов 1970–1991 (оценка, не проверена).
2. **Телефильмы и телеспектакли:** сверить со внешними списками (например, списки Википедии по годам) через `tools/xlsx_to_json.py`. Отчёт покажет, чего нет.
3. **Кинофильмы 1988–1991:** аналогичная сверка полноты.
4. **106 фильмов ГФФ (концерты и т. п.) нет в сводном xlsx владельца.** Тип им проставлен по жанру — подтвердить.

### Этап 4. Качество данных

1. **Записи не из СССР.**
   - 20 фильмов: португальские телеспектакли, «Шоу Кэрол Бернетт» (США), «Гарольд и Мод» (Болгария) и др. Список — `SELECT title, year, country FROM films WHERE country NOT LIKE '%СССР%'`.
   - Ещё «Посредник — святой отец» 1970 с пометкой «Армения» — советский фильм, ошибка в колонке страны.
   - Решить с владельцем. **Удаления в импорте нет** — добавить (например, запись `{"film_id": N, "delete": true}`: удаляет фильм, его фрагменты, эмбеддинги и строку в FTS).
2. **Студии.**
   - У 2514 из 4220 новых фильмов студия пустая, и фильтр по студии их не видит.
   - Написания разнобойные: «Одесская к/с» и «Одесская киностудия», варианты «Гл. ред. лит.-драм. программ ЦТ».
   - Нужен словарь нормализации; список студий в фильтре интерфейса сейчас зашит в HTML.
3. **Одинаковое название и год.** В базе 16 таких групп. 13 добавленных 19.10 проверены — это разные фильмы. После каждого импорта смотреть, что о таких совпадениях пишет лог.
4. **Мелочи из бэклога каталога ГФФ** — `GFF_cowork/README.md`, раздел «Что не сделано». Их судьба на усмотрение владельца.

### Этап 5. Качество поиска

1. **Новый бенчмарк.** Сейчас 85 запросов, и все про кинофильмы ГФФ. Добавить ≥ 50 запросов про телефильмы, телеспектакли и мультфильмы. Мерить до и после этапа 2 (Hit@1, Hit@5, попадание в кандидаты).
2. **Тип фильма в поиске.** Учитывать тип в тексте фрагмента («Телеспектакль. …») или в промпте реранкера. Решать только по результатам бенчмарка.
3. **Стоимость реранкера** — ~20 тыс. токенов на запрос. Проверить более дешёвую модель на том же бенчмарке.
4. **Карточка результата:** тип, ссылка на источник, число серий.

### Этап 6. Инфраструктура и техдолг

1. **Публикация** (делает владелец): репозиторий публичный → Settings → Pages → `main` / `/docs`.
2. **Тесты.** Автотестов в репозитории нет — проверки 19.10 гонялись вручную.
   - Перенести их в `tests/`: импорт (`--dry-run`, правка по film_id, дубли), пересборка FTS, `embed` с подставным клиентом, `/search` на кривые запросы.
   - Добавить маленькую тестовую базу и GitHub Actions.
3. **HTML-шаблон существует в двух копиях:** `film_search.py` и `docs/index.html` — свести к одному источнику.
4. **`GFF_cowork/scripts/p4/film_search.py`** — устаревшая копия движка. Удалить или пометить как архив.
5. **`embed` без `--resume` слишком легко запустить по ошибке.** Требовать явный флаг `--full`.
6. **Рост LFS.** Если база начнёт меняться часто, рассмотреть хранение вне истории git, например в GitHub Releases. Лимиты Releases не проверены.
