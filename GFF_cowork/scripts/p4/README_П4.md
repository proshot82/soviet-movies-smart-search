Порядок (Windows, командная строка в папке движка, где лежат `film_search.py` и `openai_key.txt`):

1. Убрать старую базу из папки движка: переименовать `gosfilmofond.db` в `gosfilmofond_old.db` (или удалить) — импорт только в ЧИСТУЮ базу.
2. Скопировать в папку движка `patch_film_search.py`, `db_check.py` (из `scripts/p4/`) и `catalog_final_v2.json` (из `state/`).
3. `python patch_film_search.py` — должно напечатать `OK: film_search.py пропатчен`.
4. `python film_search.py import catalog_final_v2.json` — ожидание в логе: `7174 импортировано, 0 пропущено`; чанки и FTS строятся тут же.
5. `python film_search.py embed` — единственный платный шаг (около 50 тыс. чанков; оценка стоимости печатается в конце). Если прервалось — `python film_search.py embed --resume`.
6. `python db_check.py` — эталон: фильмов 7174; слой один (catalog_final_v2.json); дубли title+year — 3 законные пары; дублей title+year+studio — 0; пустые поля genre 12 / studio 1 / annotation 8 / year 0.
7. `python film_search.py stats` и смок-тесты: `python film_search.py serve` → запросы из примеров на странице.

Замечание: `film_id` в базе при чистом импорте совпадает с `id` каталога (записи импортируются по порядку, пропусков нет).

## Один режим для всех (04.09.2026, вечер) — по решению владельца
Интерфейс оставлен в одном режиме: слова + смысл → перечитывание кандидатов реранкером. Убраны три переключателя (расширение запроса, выбор реранкера GPT-5.5 / thinking / выкл, «FTS-гибрид»), блок «Как устроен поиск и что значат режимы», технические числа cos/rrf у результатов и слова «чанки/эмбеддинги» в подписи внизу. Остались фильтры (десятилетие, студия, жанр), пометки уверенности, подсказка «Как искать» с одним абзацем о том, как работает поиск. Запасной ход автоматический: если реранкер недоступен (3 неудачные попытки), показывается список по слиянию с весом FTS 0.8 (`fallback_order()`) и плашка «Сервис переоценки (ИИ) сейчас недоступен…»; если не удался эмбеддинг запроса — поиск идёт только по словам с плашкой «Смысловой поиск сейчас недоступен…»; полный отказ API не роняет запрос. Параметры `expand` / `rerank_mode` / `fts` у `/search` и флаги командной строки (`--expand`, `--no-rerank`, `--effort`) сохранены для скриптов — интерфейс их не показывает. `rerank()` при недоступности модели возвращает `None` (раньше — список «по очкам» с пометкой «возможно»); `bench_search.py` и `test_search.py` считают такой случай ошибкой прогона. База, эмбеддинги и качество поиска не менялись (контрольный прогон 21:09 остаётся в силе).
