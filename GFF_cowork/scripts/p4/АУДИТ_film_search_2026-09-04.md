## Исправлено в film_search.py
1. **Результаты и статус — сразу под полем поиска и фильтрами**; блоки «Как искать» и «Как устроен поиск» перенесены ниже результатов.
2. **Видимый прогресс**: кнопка «Ищу…», секундомер, бегущая полоса, строка этапов («переформулировка → отбор → реранкер», ожидаемое время), повторный клик во время поиска игнорируется, пустая выдача сообщает «Ничего не нашлось», ошибки сервера/сети показываются красным.
3. **Браузер открывается сам** через ~1 с после старта сервера (`--no-browser` отключает).
4. **Фильтр жанра работал только на части жанров**: `LIKE` в SQLite не учитывает регистр кириллицы, «драма» не совпадала с «Драма» (ловила только «Мелодрама» и т. п.): было 492 → стало 2151 фильмов; «приключения» 2 → 334; «сказка» 26 → 97; «детектив» 8 → 109. Сравнение теперь через регистронезависимую функцию `lc()` для жанра и студии в обоих каналах (FTS и семантика).
5. **Проверка FTS-индекса при старте**: режим индекса определяется по содержимому (леммы / без лемм / устарел) и хранится в таблице `meta`; если pymorphy3 есть, а индекс без лемм — пересборка автоматически (~1–2 мин, один раз); если pymorphy3 нет — громкое предупреждение. `reindex-fts` без pymorphy3 отказывается работать (есть `--force`).
6. Предупреждение при старте, если эмбеддингов меньше, чем чанков (`embed --resume`).
7. Сервер по умолчанию слушает только этот компьютер (`127.0.0.1`); для доступа с других устройств в сети — `--host 0.0.0.0` (раньше был открыт всей сети всегда).
8. Лог без «←[31m…»: цветовые коды werkzeug вырезаются в консоли и в файле.
9. Иконка сайта встроена в страницу (нет 404 на /favicon.ico); соответствие чанк→фильм строится один раз при загрузке индекса (раньше — лениво при первом запросе).
10. В ответ `/search` добавлены `elapsed` и `candidates` (число кандидатов до реранкера — показывается в строке статуса).

Логика поиска (расширение запроса, FTS + эмбеддинги, RRF, реранкер, модели) **не менялась**; повторный импорт/эмбеддинг не нужен, база остаётся.
