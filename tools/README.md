# Как пополнять базу

Кинофильмы 1918–1987 (каталоги Госфильмофонда) закрыты — их аннотации не трогаем.
Остальное (телефильмы, телеспектакли, мультфильмы, фильмы 1988–1991) добавляется из списков xlsx.

## Добавить фильмы из xlsx

```
copy gosfilmofond.db gosfilmofond.backup.db                      # отмены импорта нет
python tools/xlsx_to_json.py список.xlsx [ещё.xlsx …] --out imports/новые.json
python film_search.py import imports/новые.json --dry-run         # отчёт, без записи
python film_search.py import imports/новые.json                   # записать (serve.bat закрыт)
python film_search.py embed --resume                              # эмбеддинги новых фильмов — ТОЛЬКО с --resume
python film_search.py stats                                       # эмбеддингов = чанков
python pages/build_site.py                                        # данные сайта → docs/data
```

Потом закоммитить `docs/data/`, `imports/` и `gosfilmofond.db` (Git LFS) и отправить в `main`.

- **Колонки xlsx** ищутся по началу заголовка: Название, Жанр, Год, Студия, Аннотация. Если есть, читаются ещё «Тип (уточнённый)», Страна, Режиссёр, Серий, Премьера, ТВ-премьера, Источник и Короткометражный.
- **Отчёт сверки:** рядом с JSON пишется `…_отчёт.xlsx` — решение по каждой строке («уже в базе», film_id, «добавить»).
- **Когда фильм считается уже имеющимся:** тот же год, то же название (целиком или без уточнения в скобках) и при этом совпадает начало аннотации или студия. Одно название и год при разных студиях и аннотациях — это разные фильмы, например кинофильм и телеспектакль «Старомодная комедия» 1978. Такие добавляются отдельно, и `import` перечисляет их в логе для проверки.
- **Тип фильма:** берётся из колонки «Тип (уточнённый)», а если её нет — определяется по жанру и аннотации. Допустимые значения: кинофильм, телефильм, фильм-спектакль, мультфильм, не игровое, фильм-опера/балет.
- **Стоимость эмбеддинга:** около $0,15 на 4000 фильмов с короткими аннотациями (1,16 млн токенов).

## Исправить фильмы, которые уже есть (например, заменить аннотацию на полную)

В JSON для `import` запись с полем `film_id` означает правку, а не новый фильм. Меняются только поля, которые указаны в записи:

```json
[{"film_id": 8327, "annotation": "Полный текст аннотации…", "source": "https://www.kino-teatr.ru/kino/movie/…"}]
```

Если меняются название, год или аннотация, у фильма пересобираются чанки, а старые эмбеддинги удаляются. Их досчитает `embed --resume`.

## Удалить фильм (например, иностранную запись, попавшую в базу по ошибке)

```
python film_search.py delete 10093 11025 --dry-run     # список к удалению
python film_search.py delete 10093 11025               # удаляет фильм, чанки и эмбеддинги, пересобирает FTS
python pages/build_site.py
```

Фильмы каталогов ГФФ (film_id < 7175) команда не удаляет.

## Полные аннотации: список работ и применение (этап 2 плана)

```
python tools/annotation_worklist.py export --estimate                        # стоимость классификации
python tools/gff_site_catalog.py                                             # каталог gosfilmofond.ru (~45 мин, с докачкой)
python tools/wiki_plots.py                                                   # «Сюжет» из Википедии (часы: лимит 429, с докачкой)
python tools/annotation_worklist.py export --classify --gff imports/gff_site_catalog.jsonl.gz --wiki imports/wiki_plots.jsonl.gz
  … владелец заполняет «Новая аннотация» и «Источник новой аннотации» …
python tools/annotation_worklist.py apply список.xlsx --out imports/аннотации_правки.json
copy gosfilmofond.db gosfilmofond.backup.db
python film_search.py import imports/аннотации_правки.json --dry-run
python film_search.py import imports/аннотации_правки.json
python film_search.py embed --resume                                         # ТОЛЬКО с --resume
python film_search.py stats
python pages/build_site.py
python pages/check_parity.py
```

- **Список работ** — только `film_id` ≥ 7175. Порядок: обрыв на «…» → «не сюжет» → от коротких к длинным. Колонка «Приоритет» — номер по этому порядку, «Поиск в Википедии» — ссылка для ручного поиска.
- **«Не сюжет»** — аннотация не говорит, что происходит в фильме (только литературная основа, жанр, тема, слава фильма). Решает `gpt-5.4-mini`, это подсказка, а не истина. Ответы лежат в `imports/аннотации_классы.json` с хешем аннотации: повторный `export --classify` платит только за новые и изменённые аннотации. Все 4220 обошлись примерно в $1.
- **`apply` не запишет JSON**, если хоть одна строка с ошибкой: film_id < 7175, film_id нет в базе, название в строке не совпадает с базой (строки сдвинули при сортировке), нет источника, новая аннотация обрывается на многоточие, film_id встречается дважды. `--skip-errors` записывает остальные строки. Аннотация, которая короче старой, — предупреждение.
- **Можно подавать не весь список**, а любой xlsx с колонками film_id, Название, Новая аннотация, Источник новой аннотации. Пустые строки пропускаются.
- **Источник** записывается в `films.source` вместо прежнего. Для Википедии — постоянная ссылка на версию статьи (`…index.php?title=…&oldid=…`): это и указание авторства по CC BY-SA 4.0. На сайте у фильма показывается первый URL из `films.source`.
- **Предложения `--gff` / `--wiki`:**
  - Колонки «Новая аннотация» и «Источник» заполняются заранее, если текст лучше текущего (правила — в `PLAN.md`, этап 2).
  - Колонка «Совпадение» показывает, как найдено совпадение; «проверить» — год ±1. Неподходящее предложение просто стереть.
  - Каждую пару сверяет модель («тот же фильм?»), ручные решения записываются в `imports/аннотации_сверка.json`.
  - Посерийный сюжет из Википедии берётся только для сериала из отдельных историй (`imports/аннотации_сериалы.json`).
- **Предложения `--web`** — пересказы, которые нашли агенты Claude поиском в интернете:
  ```
  python tools/annotation_worklist.py export --gff imports/gff_site_catalog.jsonl.gz --wiki imports/wiki_plots.jsonl.gz \
      --web imports/2026-10_пересказы_интернет.jsonl.gz --web-skip imports/2026-10_пересказы_исключены.json
  ```
  - Агент получает пакет из 25 фильмов (film_id, название, год, тип, студия, режиссёр, текущая аннотация и её хеш) и правила `imports/2026-10_правила_поиска_сюжетов.md`. Отвечает JSON Lines: `film_id, status (full / partial / keep / not_found), annotation, sources, identity, note`.
  - Берутся только `full` и `partial`. ГФФ и Википедия в приоритете.
  - Пересказ отклоняется, если после поиска аннотация в базе изменилась (хеш), если нет ссылки, если текст короче 80 символов или в нём упоминаются источники и сайты.
  - `--web-skip` — пересказы, исключённые при ручной проверке отчётов агентов, с причиной.
  - Модель тождество не перепроверяет: его устанавливает агент (поле `identity`).
  - Телеспектакль без описания постановки может получить сюжет пьесы (`basis: "play"`): принимается только у фильма-спектакля и только с пометкой «Сюжет пьесы…:» в тексте.
  - Аннотации с латинскими буквами в русских словах или с хвостом «Подробнее на Кино-Театр.РУ» без другой замены предлагаются исправленными, источник прежний.

## Мультфильмы (animator.ru + список владельца)

```
python tools/animator_catalog.py                                     # 1917–1991, ~2,5 ч, с докачкой
python tools/cartoons_merge.py imports/2026-10_мультфильмы_список_владельца.xlsx   # → imports/2026-10_мультфильмы.xlsx
python tools/xlsx_to_json.py imports/2026-10_мультфильмы.xlsx --out imports/2026-10_мультфильмы.json --default-kind мультфильм
```

- **Сверка — по animator.ru:** строк владельца без пары на animator.ru не берём. Решение по каждой строке — в `…_сведение.xlsx`.
- **Год** — из «©Студия, год г.» в аннотации владельца: он точнее колонки «Год».
- **Уже имеющиеся в базе** (то же название, год ±1) не добавляются. У не-мультфильмов решает сверка.
